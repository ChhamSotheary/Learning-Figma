# Lesson 03: Planning and Reviewing the Final Project

## គោលបំណង

រៀបចំ capstone project ពី brief ទៅ user flow, wireframes, visual design, component system, prototype និង handoff ដោយមានការពិនិត្យគុណភាពក្នុងគ្រប់ដំណាក់កាល។

## 1. បកស្រាយ Brief

សរសេរចម្លើយខ្លីៗ៖

- អ្នកប្រើគោលដៅជានរណា?
- តើពួកគេត្រូវបំពេញ task អ្វី?
- តើបញ្ហាអ្វីដែល product ដោះស្រាយ?
- តើ screens/states ណាខ្លះចាំបាច់?
- តើ constraints ឬ assumptions មានអ្វី?

កំណត់ scope ដែលអាចបញ្ចប់បាន។ សម្គាល់អ្វីដែលបានស្រាវជ្រាវ និងអ្វីដែលជាសម្មតិកម្ម។

## 2. រៀប User Flow និង Wireframes

គូស flow សំខាន់មួយពី entry point ដល់ success state ហើយបន្ថែម error/empty states ដែលជះឥទ្ធិពលលើការប្រើប្រាស់។ បន្ទាប់មកបង្កើត low-fidelity wireframes ដើម្បីផ្ទៀងផ្ទាត់ structure និង content hierarchy មុនធ្វើ visual polish។

## 3. បង្កើត Visual System

កំណត់៖

- Typography hierarchy។
- Color tokens និង semantic roles។
- Spacing និង radius scale។
- Components, variants និង states។
- Layout behavior សម្រាប់ viewport ចម្បងៗ។

ប្រើ variables/styles/components ពី Module 04។ កុំបង្កើត design system ធំជាងតម្រូវការរបស់ project។

## 4. Prototype, Test និង Iterate

ភ្ជាប់ flow សំខាន់ៗ និងសាក prototype ដោយធ្វើតាម task ដូចអ្នកប្រើ។ សួរអ្នកពិនិត្យឱ្យបំពេញ task ដោយមិនប្រាប់ចម្លើយជាមុន។ កត់ចំណុចដែលគាត់ស្ទាក់ស្ទើរ ហើយកែ design ដោយផ្អែកលើភស្តុតាង មិនមែនតាមការពេញចិត្តផ្ទាល់ខ្លួនតែប៉ុណ្ណោះ។

## 5. Final Review និង Handoff

ប្រើ checklist៖

- Screens និង flows គ្រប់ requirements។
- Responsive states មាន និងមិន overflow។
- Components មាន naming និង properties ច្បាស់។
- Colors/type មាន contrast និង hierarchy សមរម្យ។
- Prototype starting points និង interactions ដំណើរការ។
- Assets មាន export settings និង filenames ច្បាស់។
- Handoff notes បញ្ជាក់ behavior, edge cases និង open questions។
- File មិនមាន draft/duplicate layers ដែលបង្កការភាន់ច្រឡំ។

## Quick Check

1. ហេតុអ្វីត្រូវកំណត់ scope និង assumptions?
2. ហេតុអ្វីគួរធ្វើ wireframes មុន visual polish?
3. តើ user testing អាចរកឃើញបញ្ហាអ្វី?
4. តើ handoff checklist ជួយក្រុមដូចម្តេច?
