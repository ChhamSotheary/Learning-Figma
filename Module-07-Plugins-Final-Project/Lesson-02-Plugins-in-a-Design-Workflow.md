# Lesson 02: Plugins in a Design Workflow

## គោលបំណង

បញ្ចូល plugin ទៅក្នុង workflow ដោយមានចំណុចចាប់ផ្ដើម និង review checkpoints ច្បាស់ ដើម្បីឱ្យវាជួយសន្សំពេល មិនបន្ថែមការងារកែ output ដែលមិនត្រឹមត្រូវ។

## 1. Workflow មុនបើក Plugin

1. កំណត់ design task និង definition of done។
2. ពិនិត្យ built-in Figma features ជាមុន។
3. ជ្រើស plugin តែមួយដែលគាំទ្រ task។
4. ធ្វើការលើ copy/test page ប្រសិនបើ plugin នឹងបង្កើត layers ច្រើន។
5. Review output និងលុប content ដែលមិនត្រូវការ។
6. កត់សម្គាល់ plugin, inputs, outputs និង limitations។

ឧទាហរណ៍ ប្រសិនបើត្រូវការរូបភាព placeholder សម្រាប់ wireframe អាចប្រើ plugin ដើម្បីបង្កើត sample content ប៉ុន្តែត្រូវប្ដូរទៅ approved assets មុន release design។

## 2. Plugins ជាមួយ Team Libraries

Plugin output មិនចាំបាច់គោរព design system របស់អ្នកទេ។ ក្រោយបង្កើត output៖

- ប្ដូរពណ៌ទៅ variables/styles របស់ team។
- ប្រើ existing components ជំនួស generated UI controls។
- ពិនិត្យ typography, spacing និង layer naming។
- ពិនិត្យថា generated component មិនបង្កើត duplicate asset។
- យកតែ content ដែលមានតម្លៃសម្រាប់ design ទៅ library។

## 3. ការវាស់វែងប្រសិទ្ធភាព

Plugin មានប្រយោជន៍បើវាកាត់បន្ថយ manual work និងរក្សាគុណភាព។ ប្រៀបធៀប៖

- ពេលវេលាមុន/ក្រោយប្រើ។
- ចំនួន corrections ដែលត្រូវធ្វើ។
- ភាពស្របគ្នាជាមួយ design system។
- Accessibility និង quality issues។
- Permission/data risks។

បើ output ត្រូវកែច្រើនជាងការធ្វើដោយដៃ ឬបង្កើត dependency ដែល team មិនចង់គ្រប់គ្រង សូមឈប់ប្រើ ឬស្វែងរកជម្រើសផ្សេង។

## 4. អនុវត្ត

ជ្រើស task មួយក្នុង capstone project ដូចជា icon search, placeholder data ឬ contrast review។ សាក plugin លើ duplicate page រួចវាយតម្លៃលទ្ធផលតាម checklist ខាងលើ។ កុំប្រើ plugin ជំនួសការសម្រេចចិត្ត UX ឬ user research។

## Quick Check

1. ហេតុអ្វីត្រូវពិនិត្យ built-in features មុន plugin?
2. តើ plugin-generated elements អាចភ្ជាប់ទៅ design system ដូចម្តេច?
3. តើ metric ណាខ្លះអាចបង្ហាញថា plugin មិនមានប្រយោជន៍?
4. តើកិច្ចការណាខ្លះដែល plugin មិនអាចជំនួស designer បាន?
