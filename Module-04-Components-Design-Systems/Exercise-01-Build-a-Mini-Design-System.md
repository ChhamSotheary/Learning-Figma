# Exercise 01: Build a Mini Design System

## គោលដៅ

បង្កើត mini design system សម្រាប់ e-commerce mobile app ដែលអាចប្រើឡើងវិញ និងងាយប្ដូរ។

## តម្រូវការ

**Foundations**
- Color variables សម្រាប់ background, text, action និង border។
- Light mode និង Dark mode ប្រសិនបើអាចធ្វើបាន។
- Typography styles សម្រាប់ heading, body និង caption។
- Spacing/radius tokens មួយចំនួន។

**Components**
- Button មាន Primary/Secondary និង Default/Disabled។
- Text field មាន Default/Error។
- Product card មាន image, name, price និង action។
- ប្រើ Auto Layout និង component properties ដើម្បីកំណត់អ្វីដែលអ្នកប្រើអាចកែបាន។

**Consumer screen**
- បង្កើត product listing screen មួយដែលប្រើ components និង variables ពី library របស់អ្នក។
- បញ្ចូល content វែងមួយដើម្បីសាកល្បង layout។
- ប្ដូរ theme ឬ component variant ហើយពិនិត្យថា screen នៅត្រឹមត្រូវ។

## ដំណើរការ

1. កំណត់ brand direction និង accessibility/contrast needs។
2. បង្កើត variables និង styles មុន components។
3. បង្កើត Main components ហើយបន្ថែម variants តាម use cases។
4. ដាក់ឈ្មោះ assets តាម convention មួយ។
5. បង្កើត consumer screen ដើម្បីសាកល្បង component usability។
6. ធ្វើ update មួយ ហើយ review instance impacts។
7. បើ plan អនុញ្ញាត សាក publish library; បើមិនអនុញ្ញាត រក្សាទុកក្នុង file ហើយសរសេរពី limitation។

## Rubric សម្រាប់វាយតម្លៃ

- Naming និង file organization: 20%
- Variables/styles និង theme consistency: 20%
- Component structure/properties: 25%
- Usability ក្នុង consumer screen: 20%
- Documentation និង update review: 15%

## Self-review

- តើអ្នកប្រើអាចរក component ត្រឹមត្រូវក្នុង Assets បានងាយទេ?
- តើ property names ពន្យល់អ្វីដែលអាចកែបានទេ?
- តើ states និង modes មាន contrast គ្រប់គ្រាន់ទេ?
- តើ update Main component ប៉ះពាល់ consumer screen យ៉ាងដូចម្តេច?
- តើ asset ណាខ្លះមានមុខងារស្ទួន និងអាចបង្រួមបានទេ?

## Deliverables

- Figma file មាន foundations, components និង consumer screen។
- Component set មាន variants/properties។
- Variables/styles ដែលមានឈ្មោះស្របគ្នា។
- កំណត់ចំណាំពីការប្រើ theme, library plan limitation និង update review។
